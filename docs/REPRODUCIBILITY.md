# 复现说明

本文说明 WM108 时间上下文与目标时刻实验，以及 WM114 在线残差与计划复用实验的实现入口、评估协议和复现条件。`archive/` 保存实验源码，`results/` 保存已公开的结果摘要与逐例表。当前发布支持检查实现与核对已公开结果；完整模型重跑仍需补齐下述资产和环境。

## 1. 实现与实验条件

### 世界模型与规划器

WM108、WM114 使用 Temporal Straightening 的视觉世界模型和原生 GD/MPC 规划器。JEPA-WMs 提供 PushT 环境及包装接口。模型底座和评估环境的来源需要分别记录。

| 项目 | 固定条件或来源 |
|---|---|
| Temporal Straightening | [官方仓库](https://github.com/agentic-learning-ai-lab/temporal-straightening)，提交 `2c3c7666a69a730042590d548c6731259c4183ac` |
| 模型目录标识 | `pusht_aggmlpcos1e-1_resnetplus_dim8_hw14_sgTrue_lr1e-5` |
| 世界模型参数 | 基础模型保持冻结、`eval` 模式 |
| 输入图像 | 224 × 224；使用官方预处理及归档代码中的归一化常量 |
| 规划时域 | 5 个动作 token，每个 token 对应 5 个原始环境动作 |
| 闭环执行 | 每轮执行 1 个 token，即 5 个原始动作；最多 20 轮、100 个原始动作 |
| 动作优化 | 每次重新规划 100 次更新，学习率 0.1；调用官方 GD 规划器 |
| 随机种子 | WM108/WM114 规划种子为 100；环境种子由目标协议锁定 |
| 精度与设备 | 原入口固定 `cuda:0`、FP32，关闭 TF32；CPU intra-op 和 inter-op 线程数均为 2 |

加载器锁定的资产摘要：

```text

SHA256: 30b34eb854cead76287cb3796db22f9d61f725a658527003d65b3b9124634eaa

config: hydra.yaml
SHA256: 307b43a7bb72ffef7e2e604fd0d5b73b78cf33ed723990fc612738c48d690d05
```

这些摘要来自已归档加载器常量。检查点和配置文件本体不在发布包中。加载器采用 `torch.load(..., weights_only=False)` 读取对象式检查点，只应使用对应可信官方资产。

### 干预定义

WM108 对同一批开发窗口比较原生冻结规划、`deadline`、`history3` 和 `history3_deadline`。

- `deadline`：前 5 轮对预测位置 `5 - step` 计算单一目标时刻的损失，使这些轮次指向初始第 25 个原始动作时刻；之后恢复原生 `staged` 目标。这是动作规划目标，未加入模型训练损失或额外的到达后保持项。
- `history3`：输入最多 3 帧实际执行产生的 RGB/本体观测，间隔为一个动作块；过去已执行动作以停止梯度的形式加入上下文。未来优化时域仍为 5 个 token。

WM114 以 `history3_deadline` 为 B，比较 B、BR、BG、BRG：

- R：基于 Sandwich-Residuals 的本地残差实现，共 2,512 个参数；WM114 采用精确恒等初始化。仅在已完成的非终止反馈到达后更新残差，底座保持冻结。训练目标是观测预测误差，与 deadline 动作目标分开。
- G：根据冻结坐标中的预测—反馈偏差、有效动作后缀和缓存年龄决定是否复用原计划后缀；不复用时调用原生 100 次动作优化，并继续传入已有动作后缀。原协议规定相对误差阈值为 0.5、尺度下限为 0.001、最大连续复用次数为 2。这是已运行实验的设置，不是通用默认值。

门控数值由既存 WM114 `protocol.json` 的 `gate` 字段核对；原协议 SHA256 为 `491e69bfea8999fb7b3487fd61de29a647379924b5a38c084922d1f075cfdf33`。协议本体未随发布包提供，恢复其他输入与路径时仍须按资产清单处理。

## 3. 指标与配对规则

### 任务成功

主要指标采用原生 100 步成功率。环境每执行 5 个原始动作检查一次：目标与当前状态前 4 维的联合位置误差严格小于 20，且归一化到最短圆弧的角度误差严格小于 `π/9`。记录第一次满足条件的动作数并按原生规则早停。初始时刻的几何状态单独描述，不将其事后改记为第 0 步成功。

若首次成功动作数为 T，则：

- `success_by100`：T ≤ 100；100 步内未成功则为失败。
- `capped100`：成功时取 T，失败时取 100。
- `success_by25`：T ≤ 25，作为次要指标。
- `capped25`：25 步内成功时取 T，其余取 25。

因此，第 100 步成功与 100 步失败的封顶代价都为 100，仍须分别报告成功标记；第 25 步同理。不能用封顶动作数单独代替成功率。

### 同目标比较与依赖关系

WM108 使用 50 个已有开发窗口，包含 50 个复用的原生基线案例与 150 个干预案例。每个方法对同一窗口配对，窗口与轨迹分组关系须保留；200 个案例不是 200 个独立任务。

WM114 以同一窗口的 B 为对照，同时报告恢复成功和新增失败。保存结果分析器只对四臂均已完成且审计通过的窗口计算完整配对统计，并单独列出未完成项目。各方法的目标、初态、种子和环境预算必须一致。

主要结果以窗口等权统计；轨迹等权描述是补充视角。重复使用的开发窗口不构成独立确认集，描述性改善不能自动外推到其他初态、轨迹、任务或模型。

### 计算与交互成本

分别记录原始环境动作数、重新规划次数、计划复用次数、动作反向传播次数、残差更新次数、规划耗时、训练耗时、监测耗时、总耗时及峰值显存。增加历史上下文会改变每次模型调用的工作量；相同调用次数不代表相同 FLOPs。降低重新规划次数也不等于总耗时同比下降。

## 5. 资产清单与迁移步骤

### 尚缺资产

| 资产 | 对复现的影响 |
|---|---|
| Temporal Straightening 官方源码、配置和检查点 | 无法创建历史底座与原生规划器 |
| JEPA-WMs 环境的固定版本及依赖 | 无法确保动力学、图像渲染和成功判据一致 |
| WM105 目标生成记录、50 窗口清单和参考缓存 | 无法恢复完全相同的初态与目标 |
| WM105/WM108/WM114 原始协议与执行校验文件 | 无法通过输入、源码哈希和路径校验 |
| 逐轮原始输入、动作、预测、反馈、完成与审计记录 | 无法从头核对所有轨迹和重算原分析器结果 |
| WM107 的部分历史完成记录，以及 WM106 审计分支所引用的记录 | 原协议构建或特定审计分支仍会检查它们 |
| 独立的 WM114 配置生成入口 | 原准备脚本未收入发布包，现有包保留主要运行与分析实现 |

已发布的结果摘要与逐例表用于检查已报告数值，不代替上述完整原始数据。重算摘要和重新运行模型是不同的复现层次，应分别登记。

### 迁移顺序

1. **保留原始归档。** 在独立工作目录进行迁移，保留原源文件清单和摘要；迁移代码、协议与新结果使用独立版本。
2. **取得固定依赖与资产。** 按官方来源取得 Temporal Straightening 和环境依赖，核对提交、配置和检查点摘要。补齐环境版本信息，记录任何无法取得的资产。
3. **恢复输入边界。** 整理窗口标识、轨迹分组、种子与参考缓存。规划器只接收允许的 RGB、本体观测和已执行反馈；真值状态保留在重置与评估侧。
4. **明确路径映射。** 保留 `work/` 的相对层次，配置官方仓库、权重、缓存和输出目录。原协议含历史路径和源文件哈希；迁移后须生成新的、带来源映射的协议，不将更改后的协议标作原始协议。
5. **补齐配置并保留校验。** 保留窗口与方法队列、目标信息权限、随机种子、动作预算、停止规则和数据分组。WM114 门控配置应从原协议恢复；无法恢复时标注为新实验配置。迁移不应直接关闭原完整性检查。
6. **先验证底座一致性，再做比较。** 后续执行阶段需要检查预处理、动作单位、冻结参数状态、首轮动作与成功判据的一致性；随后按锁定队列运行和统计。该步骤尚未在本次发布整理中执行。
7. **区分历史复现与新确认。** 历史窗口用于对应结果复现；任何独立泛化评估另建目标、随机种子和结果目录，并在使用数据前固定主要指标与配置。
